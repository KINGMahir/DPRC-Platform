# 17. DPRC Design Language

## Purpose

The DPRC Design Language defines the visual identity, interaction principles, and user experience standards for every application, module, and platform developed within the DPRC ecosystem.

Its purpose is to ensure that every interface feels like part of one unified engineering platform rather than a collection of independent pages.

---

# Design Philosophy

The DPRC Platform is not designed as a traditional social network, corporate website, or administrative dashboard.

Instead, it is designed as an Engineering Knowledge Platform.

Every page should communicate:

* Engineering
* Research
* Innovation
* Professionalism
* Exploration
* Connected Knowledge

The experience should resemble an engineering operating system where information is interconnected rather than isolated.

---

# Core Principles

## 1. Knowledge First

Knowledge is the primary object of the platform.

Projects, technologies, people, organizations, publications, research areas, laboratories, datasets, and events are treated as entities that can evolve into independent knowledge pages.

---

## 2. Entity-Based Design

Every major object should be represented as an entity.

Examples include:

* Person
* Project
* Organization
* Publication
* Technology
* Skill
* Research Area
* Laboratory
* Event
* Dataset

Entities are connected together to form a navigable knowledge graph.

---

## 3. Progressive Discovery

Information should be revealed gradually.

Users begin with high-level summaries before exploring increasingly detailed relationships.

Navigation should encourage exploration instead of overwhelming the user.

---

## 4. Consistency

Every page should share the same visual language.

Users should immediately recognize any DPRC interface regardless of module.

---

# Visual Language

## Glass Interface

Cards use translucent surfaces with subtle blur and thin borders.

Glass panels provide hierarchy without creating visual heaviness.

---

## Motion

Motion communicates interaction rather than decoration.

Hover interactions should feel responsive and precise.

Preferred characteristics:

* Short duration
* Small lift
* Slight scaling
* Soft glow

Animations should never distract from content.

---

## Color Semantics

Color communicates entity type.

Technology → Sky

Skill → Blue

Project → Orange

Publication → Emerald

Organization → Violet

Person → Amber

Research Area → Teal

Dataset → Slate

Generic Entity → Cyan

Status indicators may use separate semantic colors.

---

## Typography

Typography prioritizes readability.

Information hierarchy is established through size and weight rather than excessive decoration.

The platform should maintain a minimal number of typography scales.

---

## Spacing

Generous spacing improves comprehension.

Whitespace is considered part of the interface rather than unused space.

---

# Information Hierarchy

Pages should generally follow this structure:

Identity

↓

Metrics

↓

Relationships

↓

Knowledge

↓

Timeline

↓

Knowledge Graph

This hierarchy represents how users naturally explore engineering information.

---

# Interaction Model

Static interface components should remain visually calm.

Interactive entities should communicate that they are explorable.

Entity chips, relationship nodes, and graph nodes should use a shared interaction language including:

* subtle lift
* glow
* activation indicator
* smooth transitions

---

# Component Categories

The design system distinguishes between interface components and knowledge entities.

Interface Components include:

* Buttons
* Inputs
* Status Badges
* Alerts
* Navigation

Knowledge Entities include:

* Person
* Technology
* Skill
* Project
* Publication
* Organization
* Research Area
* Event
* Dataset

Only knowledge entities participate in the platform's knowledge graph.

---

# Future Direction

The long-term objective is to transform the DPRC Platform into a fully interconnected engineering knowledge ecosystem.

Every entity should eventually support:

* dedicated pages
* relationships
* timelines
* references
* metadata
* graph visualization
* cross-platform linking

Every section must have its own visual identity while remaining part of the same design system.

Consistency comes from:
- spacing
- typography
- glass panels
- hover behavior
- chips
- transitions

Uniqueness comes from:
- information layout
- interaction style
- data visualization

The design language should continue evolving while preserving consistency, clarity, and professionalism.
